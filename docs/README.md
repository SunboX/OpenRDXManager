# OpenRDXManager documentation

Start with the guides below to install the application, manage a dock or resolve a failed operation.

- [Installation](installation.md): launch requirements, service access and running from source.
- [App usage](app-usage.md): discovery, status, tests and cartridge utilities.
- [Firmware updates](firmware-updates.md): selecting a release and handling reconnection.
- [Migration](migration.md): first installation and recovery with saved unit records.
- [Manufacturing backup and restore](manufacturing-backup-restore.md): preserve or restore original factory records.
- [AI agent access](ai-agent-access.md): connect an MCP client to the running application.
- [Serial utility](serial-utility.md): inspect and prepare a supported serial change.
- [Troubleshooting](troubleshooting.md): service, discovery and operation failures.

Technical material is grouped by purpose:

- [Development](development/README.md): setup and implementation notes.
- [Specifications](specs/README.md): dated design requirements.
- [Plans](plans/README.md): dated implementation and investigation plans.
- [Protocols](protocols/README.md): command layouts, record formats and vendor feature references.
- [Verification](verification/README.md): software checks and hardware acceptance boundaries.
- [Reports](reports/README.md): dated investigations and handoffs.
- [Evidence](evidence/README.md): retained screenshots and recorded physical observations.

The documentation root contains user guides. New technical documents belong in the matching subfolder and use lowercase kebab-case filenames. Dated plans, specifications and reports use `subject-YYYY-MM-DD.md`. Keep the title aligned with the filename's subject, and preserve the distinction between implementation checks and physical hardware results.
